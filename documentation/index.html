SOORA ERP User Documentation

Complete guide to managing your business with the SOORA ERP system — users, permissions, products, orders, payments, SMS, Telebirr, reports and more.

Version 1.0 6 Languages CodeIgniter 3 + MySQL Responsive

1 Getting Started

What is SOORA ERP?

SOORA ERP is a web-based business management system built for retail and service businesses in Ethiopia. It helps you run your whole operation in one place: manage your team and their permissions, build a product catalog, record sales orders, accept cash and Telebirr payments, send SMS receipts to customers, and track your income with reports.

The system is designed to be simple enough for everyday staff while giving owners full control with powerful reports and configurable settings.

Who is this system for?

SOORA ERP is built for any business that records orders every day and needs to know exactly where its money is — from one counter to many stores. It is especially made for businesses that use orders and order processing from start to finish.

🏪

Shops

Supermarkets, mini-marts, stationery, clothing and everyday shops that sell and record orders daily.

📦

Warehouses

Businesses that move stock in and out — stock counts, quantities, and knowing what is running low.

🖨️

Printing Houses

Printing and design studios that take orders for measured materials and track every print job.

📷

Photography Studios

Photography and photo studios that book sessions, sell prints, and follow up with their customers.

🧾

Businesses that Use Orders

Any business that takes an order, sells on credit, prints a receipt, or checks on what customers still owe.

Especially for you: If your day is full of orders — from cash at the counter to Telebirr payments, from one bill to dozens — SOORA ERP is built around your way of working.

Installation Guide

Tip: This section is for the person who sets up the system (site owner or administrator). If you only use the system, just go to Logging In below.
  1. Download the files. Copy the project folder into your web server's root directory. For XAMPP this is usually C:\xampp\htdocs\ERP_qubeteck\.
  2. Create the database. Open phpMyAdmin and create a new database named stock.
  3. Import the schema. Import the stock.sql file into your stock database.
  4. Run the servers. Start Apache and MySQL from your server control panel (WAMP / XAMPP).
  5. Open the system. Visit http://localhost/ERP_qubeteck/ in your browser.

Configure the database connection (if needed)

If your database user or password is different (for example a production server), edit application/config/database.php:

database.php
$db['default'] = array(
    'hostname' => 'localhost',
    'username' => 'root',
    'password' => '',
    'database' => 'stock',
    'dbdriver' => 'mysqli'
    // ...
);
Important: Never run the system on a default password on the internet. Change the database and admin passwords before going live.

Logging In

  1. Open the system URL in your browser (for example http://localhost/ERP_qubeteck/).
  2. Enter your email and password on the login page.
  3. Click Login. You will be taken to the dashboard. If you were already logged in, the system opens the dashboard directly.
Default login (for first use — change it immediately):
Email: admin@admin.com
Password: password
Sample login URL check
# If the site is inside a folder, the URL is:
http://localhost/ERP_qubeteck/auth/login
# Logout:
http://localhost/ERP_qubeteck/auth/logout

3 User Management

Users are the people who log into the system (owners, cashiers, managers). Each user belongs to one group which decides what they can see and do.

Viewing users

Go to Users → Manage Users. The list shows users in a searchable table with columns for name, phone, gender and actions. The main administrator account (id 1) is never shown in the list and cannot be removed.

Adding a new user

  1. Go to Users → Add User.
  2. Fill the form:
    • Username — a short unique name used to identify the user.
    • Password — stored securely (hashed, never readable in the database).
    • Email — used to log in.
    • First name / Last name — the staff member's name.
    • Phone — contact number (also used if SMS is enabled).
    • Gender — Male / Female.
    • Group — choose the permission group for this user.
  3. Click Create. The password is hashed before saving. You will be returned to the user list.

Editing / deleting a user

  • Edit: click the Edit icon next to a user, change the details and save. You can also set a new password here — the confirmation field must match.
  • Delete: click the Delete icon. Only users with the "delete user" permission can do this.

Profile & Settings (your own account)

  • Profile — shows the details of the currently logged-in user. Always available to the logged-in user.
  • Settings — lets a user update their own information and change their own password (enter your current password logic: new password + confirmation must match).
Warning: Do not delete or disable the only user with administration rights — you could lock yourself out of the system.

4 Roles & Permissions (Groups)

A group is a set of permissions. Instead of giving permissions to each person, you create groups (for example Cashier, Manager, Owner) and assign users to them.

The 36 permissions

Every module has four standard permissions (create, view, update, delete) plus a few special ones. Examples:

PermissionWhat the user can do
createProduct / viewProduct / updateProduct / deleteProductWork with the product catalog.
createOrder / viewOrder / updateOrder / deleteOrderWork with orders and payments.
createUser / viewUser / updateUser / deleteUserManage staff accounts.
viewReportsSee sales charts and detailed income reports.
updateCompany / updateSettingChange company settings and system configuration.
createCustomer / viewCustomer / updateCustomer / deleteCustomerManage organization customers.

Permissions are checked on every action by the system. Even if a user navigates directly to a URL, they only succeed if their group has the permission.

Creating and managing groups

  1. Go to Groups → Add Group. Enter a group name.
  2. Tick the permissions you want this group to have. The list is grouped by module for easy selection.
  3. Save. The group appears in the group list and can be assigned to users.

You can edit a group's permissions at any time — the change applies to every user in that group immediately.

Cannot delete? A group that is assigned to at least one user cannot be deleted. Reassign or remove the users first.
Pre-configured groups: Two full-access groups are created for you: Administrator and Owners — both have all 36 permissions.

5 Product Catalog

The catalog holds everything you sell. It is organised with products plus supporting lists: brands, categories, stores and attributes. Products use these lists to describe themselves (a product belongs to a store, can have one or more brands / categories / attributes, and carries its own price and stock quantity).

Brands

Brands are the makers of your products (for example "Habesha", "Rico", "Samsung"). You can mark a brand active or inactive. Use Brands in the menu to add, edit or delete, and to set whether the brand is active.

Categories

Categories group your products into types (for example "Printing", "Stationery", "Clothing"). Manage them under Category. You can activate or deactivate a category, and products keep their category even if a list item is later made inactive.

Attributes

Attributes describe product options in two levels: an attribute (for example "Color" or "Size") and its values (for example Blue, Red / S, M, L). Create an attribute, then open it and click Add Value to add its values. Attribute values are stored with the product record (as JSON) so a product can carry several.

Stores

Stores are your locations or warehouses (for example "Chiro Main Shop", "Store 2"). Each product is assigned to a store. The dashboard shows the total number of active stores.

Products — field by field

FieldDescription
NameThe product name shown to customers.
SKUStock Keeping Unit — a unique code for the product.
PriceSelling price in the selected currency.
QuantityCurrent stock level. Automatically decreased when an order is placed.
ImageProduct image (GIF / JPG / PNG, max 1 MB).
DescriptionA short description of the product.
Brand / Category / StoreWhich brand(s), category(ies) and store this product belongs to. Multiple brand / category assignments are supported via JSON.
Attribute ValueOptional attribute values selected for this product.

Stock levels: Quantity ≤ 10 is shown as a Low Stock warning. Quantity ≤ 0 is shown as Out of Stock.

Adding and managing products

  1. Go to Products → Add Product.
  2. Enter the product details (name, SKU, price, quantity, image, description).
  3. Assign brand(s), category(ies), attribute value(s) and a store.
  4. Set availability and click Create.

Use Products → Manage Products to view the catalog. The list shows a thumbnail, SKU, name, price, quantity status (with low-stock colouring), store and availability. You can edit or delete products from here.

6 Orders & Sales

Orders are the heart of the system. There are two types: private / individual orders (customer information is typed into the order) and organization orders (linked to a saved customer record). Every order can hold several products, plus optional dimensions, discounts, service charge and VAT.

Order types

TypeDetail
Private / Individual OrderCustomer name, address and phone are entered directly on the order screen (menu: "Add Order").
Organization OrderLinked to a saved organization customer — you pick the customer and their details are pulled in (menu: "Add Organization Order").

Creating an order

  1. Choose the order type (Add Order for private, Add Organization Order for organizations).
  2. Select products. Add products to the order — for each one set the quantity; for measurement-based items (e.g. glass), enter the height and width and the area (kaaree) is calculated automatically.
  3. Set customer details (name, phone, address) — or pick an existing organization customer.
  4. Apply charges and discount — service charge and VAT/TOT are calculated automatically from the rates set in company settings. You can also enter a discount.
  5. Save the order. Stock is reduced automatically for every product sold, and an SMS receipt is sent if SMS is enabled.
Bill number: The system creates a unique bill number from the last 5 digits of the customer's phone plus a counter — for example 12344-0001.
Stock is automatic: Placing an order reduces product quantity. Editing an order restores the old stock and re-deducts for the new items, so your stock always stays accurate.

Viewing and editing orders

  • Manage Orders — lists all private orders (searchable table).
  • Manage Organization Orders — lists all organization orders.
  • Click Edit to change products, quantities, customer details or discounts. The order and its stock are recalculated.

Payments

Each order has a payment status and a payment history. You can record multiple payments against one order (useful for installments on loans).

Payment statusDescription
PaidThe order is fully paid.
Advance PaymentCustomer paid only part (advance/partial).
Loan / UnpaidNo payment yet — a credit/loan order (the dashboard tracks the total loan amount).

Payment methods: Cash, Bank Transfer, Mobile Transfer, and Telebirr. The order payment screen also lets you enter a Telebirr transaction number; the system can verify it automatically (see Telebirr Verification). When a payment is recorded, an SMS confirmation is sent if SMS is enabled.

Payment types used by the system
payment_types:  0 = Cash
                1 = Bank Transfer
                2 = Mobile Transfer
                3 = Telebirr

paid_status:    0 = Loan / Unpaid
                1 = Paid
                2 = Advance Payment

Order processing workflow

Orders move through three states. Use the Order Process page to update them.

StepDescription
Not ProcessedOrder received, work not started.
Under ProcessWork is in progress.
DeliveredOrder completed and handed to the customer.
  1. Open Order Process from the menu.
  2. Choose an order and set its status (Not Processed / Under Process / Delivered).
  3. Save. Each status change is recorded with the date, and a status-change SMS is sent to the customer if SMS is enabled.

Printing receipts

Every order can print a receipt/invoice. The receipt is optimized for thermal printers and uses your configured paper size (for example 80 mm wide x 297 mm). It prints automatically when the page opens and is written for your local audience (in Afan Oromo). It shows the bill number, customer, items, gross amount, service charge, VAT, discount and net amount.

VAT/TOT (15%):               150.00

Printer tip: Receipt text follows the paper width you set in Configuration → Printer. For standard A4 invoices use a larger width.

9 SMS Notifications

The system can send SMS messages to customers automatically using the Ethiopian GeeSMS gateway. Messages are sent when an order is created, when an order status changes, and when a payment is received.

Setting up SMS

  1. Get a GeeSMS API token from geezsms.com/#/api.
  2. Go to System Configuration → Company tab.
  3. Enable SMS set the API token and (optionally) the shortcode ID.
  4. Click "Send Test SMS" enter a phone number and a test message to check that the API works.

When SMS is sent

  • Order created — confirmation to the customer.
  • Order status changed (process step updated).
  • Payment received — receipt/confirmation SMS.

Phone numbers are normalised to Ethiopian international format (for example 0911... → 25191...). If an SMS fails (bad credit, offline), the order still succeeds — SMS never blocks a sale.

SMS log

The SMS Log page shows every message sent: order/bill, phone, message text, type (order_created, status_change, payment), delivery status and the raw API response. Use it to diagnose undelivered messages.

GeeSMS API (REST)
POST https://api.geezsms.com/api/v1/sms/send
Headers :  Content-Type: application/json
Body    :  {
             "token": "YOUR_API_TOKEN",
             "to": "251911223344",
             "message": "Your order is ready!",
             "shortcode": "SHORTCODE_ID"
           }

10 Telebirr Payment Verification

When a customer pays with Telebirr, the system can verify the payment automatically by checking the official Ethio Telecom receipt page. This protects you against fake payment screenshots.

How verification works

  1. Customer pays via Telebirr and shares the transaction number (the 10+ digit TT number).
  2. Enter the TT number on the order payment screen.
  3. The system checks the receipt using transactioninfo.ethiotelecom.et and verifies that:
    • the transaction was found,
    • its status is Completed,
    • the payment was made today, and
    • the credited account matches one of your configured Telebirr accounts.
  4. Result is shown — verified, or a reason why not (not found / not completed / wrong account).
Verification status fields:
  • found — whether the receipt exists.
  • verified — found + completed + paid today + account matches.
  • account_matches — whether the credited account is in your account list.

Requirements

  • An Internet connection from the business server to Ethio Telecom.
  • Your Telebirr accounts added in Payment Accounts with category telebirr.
Note: Verification only confirms the payment reached one of your accounts today. Always also check that the paid amount matches the order total.

11 Reports & Analytics

Reports help you understand your income. You get both a visual yearly chart and a detailed, filterable list of every payment.

Monthly income chart

  • Shows total sales per month for a chosen year as a bar chart.
  • Choose the year from the dropdown (available years are listed automatically).

Sales detail report

  • Filter payments by a date range and see each payment record.
  • Columns include: bill number, customer name, customer type, datetime, total amount, paid amount, due amount, payment type and payment status.
  • Use it to see who still owes money (due amount > 0) and to reconcile cash, transfer and Telebirr payments.
Permissions: Only users whose group includes viewReports can open the reports pages.

Typical usage

  1. Open Reports → Income Report for the chart, or Sales Detail for the list.
  2. Pick the year or date range.
  3. Review/export — the detail table supports searching, sorting and pagination.

14 Troubleshooting

Common problems and how to fix them.

  1. Check Apache is running in WAMP/XAMPP.
  2. Check the URL matches your project folder name (e.g. http://localhost/ERP_qubeteck/).
  3. Enable mod_rewrite in your Apache config; the system uses the bundled .htaccess.
  4. Check the MySQL database "stock" exists and was imported.
Your user group does not have the permission for that page. Ask the administrator to add the permission to your group, or log in with an administrator account.
The image must be GIF, JPG or PNG and smaller than 1 MB. Reduce the file size and try again. Also check the server's file upload limits (upload_max_filesize in php.ini).
The system restores and re-deducts stock when an order is edited. If numbers still look wrong, check that no other user edited the same order/stock at the same time, and review the order's item list. Contact support if it persists.
Check that you entered the exact TT number, that the payment was actually completed, and that your server has Internet access to transactioninfo.ethiotelecom.et. If the customer paid before midnight, it will not pass the same-day check today.
Dashboard and report figures are calculated from orders and payments. Refresh the page (F5) to get fresh numbers. If a report seems wrong, filter the sales detail report by date and compare payment records.
Make sure the MySQL service is running. Check application/config/database.php for the correct hostname, username, password and database name. On large databases, keep the number of open browser tabs low.

16 Privacy Policy

Last updated: 2026

1. Who we are

This documentation and the SOORA ERP system are provided by the business running the system (your company). This policy explains how the system handles information.

2. Information the system stores

  • Account information — usernames, email addresses, names, phone numbers and password hashes of staff users.
  • Business data — products, orders, customers, payments and reports entered while using the system.
  • Customer contact details — names, addresses and phone numbers of individuals and organizations you sell to.
  • SMS data — for numbers enabled for SMS, message logs (order, status and payment notifications) retained for delivery tracking.

3. How information is protected

  • Passwords are stored with strong, one-way hashing (bcrypt). No plain-text passwords are kept, and nobody, including administrators, can read them.
  • Access to each area is controlled by permissions set per user group.
  • The system runs on your own server, so your data stays on your infrastructure and under your control.

4. Data sharing

The system shares only what is necessary to provide its functions: SMS messages are sent through the GeeSMS gateway; Telebirr verification queries Ethio Telecom's receipt service with the transaction number you provide. Data is not sold to third parties.

5. Data retention and your rights

Data is retained as long as your business needs it. As a business owner you may export or delete business records at any time. Employees and customers should contact the business operating the system to request access, correction or deletion of their personal data.

6. Changes to this policy

We may update this policy as the system grows. The latest version is always published here with a revision date.
